# DR 資料の規格

ユーザーが「どの IC のどのピンが、何のために、どこへつながるか」を目視で確かめる（DR）ための、回路図と解説の一式を **DR 資料** と呼ぶ。
回路を設計・変更したら、該当する階層の DR 資料を同じ変更の中で作る・直す。

## 1. 3 種類の文書

| 種類 | 書く内容 | 作り方 |
|---|---|---|
| **正本** | 事実。どの部品があり、どのピンがどのネットにつながるか、そのネットは何のためか | 人が JSON で書く。同じ事実は 1 か所にだけ書く |
| **生成物** | 図と表。回路図、配線表、IC 一覧、信号辞書、検査結果 | 正本からスクリプトが作る。直すときは正本を直して再生成する |
| **解説** | 理由。なぜその IC か、なぜその値か、どの位相で何が起きるか、何で確かめたか | 人が Markdown で書く。ピン番号とネットは生成物を指し、解説には写さない |

## 2. 階層

| 階層 | 対象 | 正本 | 生成物 | 解説 |
|---|---|---|---|---|
| システム | 全カードとカード間配線 | `hw/system.json` | `docs/design/generated/`（全体図、IC 一覧、基板とカード、LED 一覧、基板をまたぐ信号、信号辞書。ネットごとの電流・レベル計算は未実装で、生成器の拡張で足す） | `docs/design/SYSTEM.md` |
| カード | カード 1 枚 | `hw/cards/<card>/card.json` | `WIRING.md` / `<card>.kicad_sch` / `svg/<card>.svg` | `hw/cards/<card>/DESIGN.md` |
| IC | 型番 1 つ | `hw/pinspec/<型番>.json`（ピン）、`hw/elec/<実型番>.json`（電気特性） | — | 各 JSON の `source` と `note` |

システム階層の生成器は `scripts/gen_system.py`。全体図・IC 一覧・信号辞書は `docs/design/generated/README.md` に出るので、`SYSTEM.md` には写さず、そこを指す。

## 3. システム階層の解説 `docs/design/SYSTEM.md`

章立ては固定する。

1. **全体図** — IC 単位のブロック図。箱は IC（参照名・型番・載るカード）、線はバスか制御信号（信号名つき）。データの流れと制御の流れを別の図にする。生成物を指す。
2. **IC 一覧** — 載せる IC すべて。参照名、汎用型番、採用実型番、役割、載るカード、外すと欠ける機能、pinspec の有無。生成物を指す。
3. **信号辞書** — カード間を渡る信号すべて。名前、幅、極性、駆動元、受け先、確定している位相。生成物を指す。
4. **制御表** — 命令 16 種 × 制御信号の真理値表と、各制御信号の論理式。
5. **クロック位相** — 1 命令の中で、いつ何が確定し、いつ書き込み、いつ状態が変わるか。素子の規定値（セットアップ・ホールド・パルス幅）との対応。
6. **電気規格** — カード境界のレベル、重い負荷の一覧、LED の駆動、電源電流の見積もり、出典。
7. **基板構成と LED** — 基板の分け方、接続口、表示する LED の範囲。
8. **検証記録** — 何を何と突き合わせたか、件数、日付。
9. **決定の記録** — 確認事項と、それを決めた `docs/REQUIREMENTS.md` の決定事項の対応。未決の確認事項があるうちは、ここに番号つきで並べる。
10. **カード設計で決めること** — システム設計では決めず、カード設計に回した項目。

## 4. カード階層の解説 `hw/cards/<card>/DESIGN.md`

章立ては固定する。該当しない章は「なし」と書いて残す。

1. **役割** — 担う役割（スロット）と、このカードを外すと欠ける機能。
2. **動作** — IC ごとに、機能表のどの行・どのモードを使うか（出典の DocID・頁）。
3. **配線の要点** — ネットのまとまりごとに、そうつなぐ理由。ピン番号は `WIRING.md` を指す。
4. **未使用の処理** — 未使用ピン・未使用ゲートの扱いと、その根拠。
5. **電気計算** — プルアップ値、ネットごとの電流とレベル、消費電流。式と出典つき。
6. **タイミング** — このカードの信号が、どの位相までに確定し、どの位相で取り込まれるか。
7. **検証** — 生成時の検査結果、ERC、信号レベルのモデルと `sim/machine.py` の突き合わせ結果。
8. **目視チェックリスト** — ユーザーが見る項目を `- [ ]` で並べる。1 項目 = 1 つの見る場所（どの図・表のどこ）と、合っていると判断する基準。
9. **差し替え** — 同じ役割の別カードとの違い（コネクタ信号、極性、電気的な差）。

## 5. 正本に書く事実

`card.json` の書式は `hw/README.md`。DR のために、次を正本に持たせる。

- 部品ごと: 参照名、汎用型番、採用実型番、役割。
- ピンごと: 接続ネット。未接続は `NC` とし、理由を添える。
- ネットごと: 用途の一文（何を運び、どこから来てどこへ行くか）。生成物の配線表と回路図に出る。
- コネクタ: 信号の並び。同じ役割のカードは並びを揃える。

信号名は ASCII。L アクティブは末尾に `_n`。バスは `A0`〜`A7` のように番号を付け、ビット 0 を最下位とする。

## 6. 完了条件

カードは、次のすべてを満たしたとき `status` を進める。

| 条件 | 確かめ方 |
|---|---|
| 全 IC の全ピンに、接続ネットか理由付きの `NC` がある | 生成時の検査 |
| 入力ピンがすべて、駆動元・プルアップ・電源のいずれかにつながっている | 生成時の検査 |
| 各ネットの駆動元が 1 つ。3 ステートとオープンコレクタの共有ネットは、同時に有効な駆動元が 1 つ以下であることを制御表で示してある | 検査 + `DESIGN.md` 3 章 |
| オープンコレクタのネットにプルアップがあり、値の計算がある | `DESIGN.md` 5 章 |
| 全ネットで、受け側の入力電流の合計 ≤ 駆動側の IOL・IOH、VOH ≥ VIH、VOL ≤ VIL | `DESIGN.md` 5 章（一次資料の値） |
| 全制御信号が制御表にあり、信号レベルのモデルが全命令で `sim/machine.py` と一致する | `sim/tests/` |
| 数値のすべてに、出典（DocID・頁）か計算式がある | `DESIGN.md` |
| 検査の警告 0、ERC 0 | `gen_card.py --erc` |

`status` の進み方:

| 値 | 意味 |
|---|---|
| `draft` | 設計中 |
| `checked` | 上の表をすべて満たした（エージェントが確認） |
| `reviewed` | ユーザーが目視チェックリストを確認した（日付を `DESIGN.md` 8 章に記す） |
| `frozen` | 基板化済み。変えるときは新しいカードを起こす |

## 7. 図の約束

- カードの回路図は、IC を **実物の DIP と同じピン並び** の箱で描く（左列が 1 番から下へ、右列が下から上へ）。基板上の IC と見比べられる。
- 全体図は、同じ役割の IC を箱 1 つ、バスを線 1 本で描き、信号名と幅を添える。データの流れと制御の流れは別の図に分け、1 枚あたりの線を 20 本程度までにする。
- 位相は時間軸の表かタイミング図で示し、素子の規定値と余裕を並べる。
- GitHub 上で見られる形式（Markdown の表、Mermaid、SVG）にする。
- 見やすさを優先した清書図（配置を人が決めた全体図、位相の一覧、カードの中の構造図など。`AGENTS.md` 設計ルール 12 の閲覧用の図面）は `docs/design/images/` に PNG で置き、一覧と書き出し日を同じフォルダの `README.md` に書く。作図は Claude Design のキャンバスで行い、PNG を画像編集で直さない。正本は `hw/system.json` と `SYSTEM.md` で、正本を変えたら清書図も作り直す。食い違ったら正本を正とする。

## 8. 一次資料の引き方

- 一次資料は、その IC のメーカーが出した資料（原本がメーカーのものならミラー経由でも可）。照合手順と信頼度の基準は `collection/AGENTS.md` の「対話型ファクトチェック手順」。
- 引くのは数値と出典（DocID・改訂・頁・表の名前・照合日・読み取り信頼度）。本文・図表は転載しない。
- 電気特性は実型番ごとに違う（同じ 74x181 でも S と LS で入力電流が 5 倍違う）。汎用型番ではなく、採用する実型番の表から引く。
